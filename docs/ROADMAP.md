# MASA Salon Intelligence 開発ロードマップ

## 文書の位置づけ

この文書は、`PRODUCT_SPEC.md` の仕様に基づく実装順序、進捗、依存関係、完了条件を管理する。

## 進捗状態

- `PLANNED`: 確定仕様に基づく実装予定
- `NEXT`: 次に実装する対象としてユーザーが確認済み
- `IN_PROGRESS`: 実装中または一部実装済み
- `BLOCKED`: 仕様の判断または前提待ち
- `DONE`: 実装と必要な確認が完了
- `CANCELLED`: 採用中止
- `FUTURE_DRAFT`: 将来構想であり、実装確定前

## 優先順位の原則

1. まず日々の実績入力と正確な集計を完成させる。
2. 機能を無制限に増やさない。
3. 依存関係上、順序変更が必要な場合は、理由と影響をユーザーに説明し、確認を得る。
4. `DRAFT` または `UNDECIDED` を、確定済み実装項目として扱わない。

### フェーズ1の対象と完了状態

#### F1-000 営業日状態の区別

- 状態: `DONE`
- 対応仕様: PRODUCT_SPEC 3.2
- 目的: `businessStatus` で `open`、`closed`、`unset` を区別する。
- 保存ルール: 未保存日は `unset`、通常の営業設定保存は `open`、明示的な休業保存は `closed` とする。
- 登録制御: `closed` の日は来店実績を登録不可とし、臨時登録では先に `open` として営業設定を保存する。
- 依存関係: 現行の日別データとの互換方針

#### F1-000A 実績の確定値と過去表示の保持

- 状態: `DONE`
- 対応仕様: PRODUCT_SPEC 3.1
- 目的: 来店実績に `standardPriceAtVisit` と `staffNameAtVisit` を追加し、既存の `price` と `staffId` を維持する。
- 修正ルール: 売上または所要時間だけの変更では `standardPriceAtVisit` を変更しない。担当者変更で `staffId` と `staffNameAtVisit`、メニュー変更で `menuId`、`menuName`、`standardPriceAtVisit` を更新する。
- A（改名後の過去メニュー名の書換え）・B（削除済みメニューの自動置換）は修正済み。メニューIDが変わらない修正では3つのメニュー情報を保持する。再現・回帰確認に加え、担当者履歴の追加検証も完了。
- 依存関係: 現行保存データとの互換方針

#### F1-000B 入力条件と日次売上指標

- 状態: `DONE`
- 対応仕様: PRODUCT_SPEC 3.1、3.5
- 目的: 担当スタッフ必須、30分刻み、技術売上基準の客単価、総売上の別表示を完成させる。
- 担当者必須、追加・修正時の30分刻み保存検証、客単価・日次集計を確認済み。総売上は `技術売上 + 店販売上` を表示時に計算し、保存しない。時間単価・稼働率の既存計算を維持し、回帰確認済み。
